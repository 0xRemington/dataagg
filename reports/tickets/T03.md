## Behaviour

- **Immutability:** observation tables are append-only, enforced by triggers. Published batches are sealed. Revisions, parser corrections and invalidations append linked rows; nothing is updated in place.
- **Publication:** stage, then publish. A staged batch has no `known_at`. Crash recovery publishes with the *recovery* time, so the known time is conservative. Publishing can never backdate before `recorded_at`.
- **Clock skew:** skew above the limit suspends publication and records an incident in its own transaction. A bug that rolled the incident back with the failed publish was found and fixed here.
- **Idempotency:** replaying a response is idempotent through `response_identity`, and concurrent staging of one response creates one batch. Distinct polls persist even when prices are equal.
- **Partitions:** a validated partition function with no default partition. A missing partition is a readiness failure.
- **Roles:** least privilege. Runtime roles cannot alter schemas or drop partitions.
- **Downgrades:** refused unless the database is disposable and the caller opts in.

## Production fixes (2026-10-26)

- **Role-based startup failed.** Services upserted reference rows at startup, which the ingest and reader roles may not write. Provider and policy registration now read first. The owner writes reference data in `marketagg migrate --bootstrap`. A non-owner role that meets missing or stale reference data gets a clear `InvariantViolation`. The read-only API skips partition provisioning.
- **Backup role could not read new partitions.** Migration `0007_partition_grants` adds default privileges and a catch-up grant so `pg_dump` can lock partitions created after 0004.
- **New tests:** `tests/integration/test_role_bootstrap.py` runs bootstrap and backup under the real group roles. Other integration tests connect as a superuser and could not catch either problem.
