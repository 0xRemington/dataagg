## Decisions

- Python `>=3.12,<3.13`, build backend `uv_build`. Runtime dependency: `pydantic` only. Dev extra: `ruff`, `mypy`, `pytest`. Resolved versions are pydantic 2.14.1, mypy 2.4.0, pytest 9.1.1 and ruff 0.17.2, pinned in `uv.lock`. T03 adds SQLAlchemy, psycopg and Alembic through the integrator.
- Settings are a frozen Pydantic model with no `pydantic-settings` dependency. Only the variable names in `ENV_FIELDS` are read. Precedence is profile, then `--env-file`, then the environment.
- The CLI uses argparse. Exit `2` means invalid configuration. `--json` gives machine-readable output.
- Logs are one JSON object per line with `ts` in UTC `Z`. Redaction covers registered secret values, bearer tokens, `token=`/`password=`/`secret=`/`api_key=`/`authorization`/`cookie` pairs, URL userinfo passwords, structured `extra` fields and exception text.
- Ruff runs with `PLR0913`, `PLR0917` and `PLR2004` ignored. Mypy runs in strict mode with the pydantic plugin.

## Handoff

- New subcommands go through the integrator in `cli.py:_build_parser`.
- Any later dependency must be added with `uv add` by the integrator only, so `uv.lock` stays single-writer.
- Services should call `configure_logging(settings.log_level, secrets=[read_secret(p).get_secret_value() ...])` after reading their secret files. This registers the exact values for redaction.
