## Measurement (`measure_capacity`)

It measures the last N calendar sessions with 1m data, or the sessions ending at `--last-session`, from what the database recorded. Nothing comes from configuration.

- **Requests:** endpoint and transport totals, effective rate per minute, and peak per minute over open−30m … close+30m.
- **Errors:** counts by code.
- **Chain coverage:** per `(symbol, expiration)` scope, a slot counts as covered only if the job succeeded and its run finished within 120 s of the slot. Skipped, shed, failed and partial slots are counted separately.
- **Minute coverage:** per symbol against the calendar's expected minutes.
- **Lag:** p50/p95 of `known_at − fetch_completed_at` per batch kind.
- **Option rows and event time:** option row counts, plus the ratio of rows with a known quote event time. This produces `freshness_claim=collection_cadence_only` unless every row has a provider event time.
- **Storage:** relation sizes over partition trees, bytes per row with indexes, database, payload, archive and WAL bytes.
- **Headroom:** projected days until the lower of the 80% stop-bulk disk limit and `MAX_LOCAL_DATA_GIB`, using the measured bytes per stored session.
- **Backups:** verified backups that overlapped a pilot session.

## Release gates (`evaluate_release`), all mandatory

Each gate passes only on the condition shown.

| Gate | Passes when |
|---|---|
| capacity_report_present | `capacity.json` exists |
| live_source_measured | provider is not `fake` and the data is live |
| five_sessions | at least 5 sessions with recorded requests |
| source_review_approved | `feasibility/live/<provider>/source-review.md` has `Release decision: APPROVED` and no `UNRESOLVED` |
| acceptance_signed_off | latest acceptance manifest checksum matches, `signed_off`, A01–A09 and temporal adversaries passed |
| offsite_restore_drill | A07 RTO measured, and at least one verified backup during a pilot session |
| priority_chain_coverage | min per-scope on-time coverage ≥ 0.95, **or** a published `cadence-limitation.json` with a measured cadence above 5 min |
| skipped_scopes_counted | every session reports skipped slots |
| minute_coverage | ≥ 0.99 |
| processing_lag | worst p95 ≤ 5 s |
| disk_headroom | ≥ 30 projected days |
| request_budget | peak utilisation ≤ 0.70 |
| no_execution_grade_freshness_claim | claim is `collection_cadence_only` unless event times are fully known |
