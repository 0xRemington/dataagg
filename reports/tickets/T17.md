## Behaviour

- **Compose:** digest-pinned images and a private internal network with no host DB port. API and UI bind to loopback only. The one-shot `migrate` service gates the app services. Containers are read-only, run non-root (UID 10001) with all capabilities dropped, have no Docker socket, and the UI holds only the read token.
- **Backups:** AES-256-GCM in 1 MiB chunks, with chunk index and final flag authenticated, so truncation and reordering are detected. The manifest is HMAC-authenticated.
  - A backup covers the DB dump **and** every referenced archive/payload object.
  - A missing object aborts the backup.
  - Restores only go into a *new* database and an empty storage root.
- **Operator status:** reports stalled ingestion per scope, unknown freshness, backlog, disk and backup staleness. Notifications stay disabled until a destination is configured.
- **Disk policy:** warn at 70%, stop bulk work at 80%, suspend collectors at 90%.

## Live deployment (2026-10-26)

**Host:** AWS Lightsail-class VPS, public IPv4 3.96.212.84, 2 vCPU, 3 GiB RAM plus 2 GiB swap, 77 GB disk, Ubuntu 24.04. Docker 29.1.3 and Compose 2.40.3 were installed from Ubuntu packages.

**Public access (operator decision):** Caddy 2.10.2 (digest-pinned) on `0.0.0.0:8000`.
- The dashboard is behind basic auth. `/v1/*` goes to the API with bearer tokens.
- Database, API and UI publish no host ports.
- Plain HTTP; TLS needs a domain.

**Fixes found while deploying:**
- **Loopback ports never worked.** Containers on an `internal`-only network cannot publish ports, so the original API/UI loopback ports were never reachable. The proxy is now the single entry point.
- **The worker had no internet access.** The internal network has no egress; the worker and proxy now also join an `egress` network.
- **Proxy failed to start.** The Caddy binary needs `NET_BIND_SERVICE` in the bounding set, or exec fails under `cap_drop: ALL`.
- **Containers couldn't read secrets.** File secrets keep host ownership, so `setup_secrets.sh` uses group 10050 (`group_add`), and uid 999 for the DB owner password.
- **Root-owned volumes.** `/data` and `/backups` were not writable by uid 10001. The Dockerfile now creates them owned by the app user, and the existing volumes were chowned.
- **Scheduler crash loop.** Log `extra={"created": ...}` collides with a LogRecord attribute. Fixed, with an AST regression test.
- **Worker crash loop.** One job's unexpected exception killed the whole worker. It now opens an incident and retries with bounded backoff before failing that job.
- **Memory limits** were resized for 3 GiB: db 1 GiB with shared_buffers 256 MB, worker 768 MiB, API/UI 384 MiB, proxy 128 MiB.

**Operations:**
- `marketagg-backup.timer` takes a verified backup daily at 17:00 UTC. The first backup verified with 11 objects.
- **The backup destination is still on this host** (volume `marketagg_backups`). Off-host copies and a copy of `secrets/backup_key` elsewhere are the operator's open items.
