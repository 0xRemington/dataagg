## Behaviour

- **Timing and sizes:** quote event time and bid/ask sizes stay null. `last_trade_at` is never used as quote time.
- **Missing vs zero:** NaN means not reported; zero stays zero. pandas turns `None` into a truthy NaN, which first broke missing-identity classification; that was fixed.
- **Rejected rows:** infinite values and bad symbols are rejected per row. Adjusted roots are kept and flagged, and the multiplier is never inferred from the symbol.
- **Schema drift:** a renamed or retyped column raises `SchemaChanged` with a fingerprint.
- **History:** requests are unadjusted, and the price basis is flagged.
- **Live access:** the real client requires the live gate (`LiveAuthorization`). The live probe requires a review ID.

## Live qualification (2026-10-26)

The operator approved the source: decision `operator-2026-10-26`, recorded in `reports/feasibility/live/yahoo/`. The first live probe found two adapter defects, both fixed and covered by contract tests (18 tests):

- **Every history bar was rejected.** Yahoo's chart API sends prices as float32. yfinance widens them, so 767.23 arrives as 767.22998046875, and that exceeds `numeric(20,8)`. Prices that are exactly float32 now map to their shortest float32 representation, which is the value Yahoo sent. The mapping version is now `yahoo-map/2`, and the test fake now emits float32-widened prices. Chain quotes were never affected.
- **No-bar windows tripped the circuit breaker.** For a window without bars (weekend), yfinance raises `YFPricesMissingError` ("possibly delisted"). The adapter mapped this to `Unavailable`; it now returns an inconclusive `empty` result.

Live probe after the fixes: SPY and QQQ discovery ok, chains of 237 and 232 rows, 20 daily bars over 30 days, 1,950 one-minute bars over 7 days. The 1-day weekend window is correctly empty.
